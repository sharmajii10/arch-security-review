# ISO/IEC 27001 — Architecture Review Lens (Annex A themes)

Original guidance organized around Annex A theme areas relevant to a system diagram — not the standard's text. Cite by theme area rather than quoting control wording.

## What to look for in the diagram

**Network security (Annex A — network controls)**
- Are network zones/segments actually drawn, or is it one flat diagram? Segmentation between public-facing, application, and data tiers is the baseline expectation.
- Any exposed management interfaces (admin panels, DB ports) reachable from a less-trusted zone?

**Cryptography (Annex A — cryptographic controls)**
- Same lens as PCI's Req 3/4 but framed generally: is encryption-in-transit labeled on flows carrying sensitive data? Is there a key/secrets management component, or is key handling unaddressed in the diagram?

**Access control & identity (Annex A — access control, identity management)**
- Is there a centralized identity/authorization component, or does each service appear to handle its own auth (higher risk of inconsistency)?
- Privileged/admin access paths — are they distinguished from standard user paths?

**Secure system architecture & engineering (Annex A — secure development/architecture)**
- Are there separate environments implied (dev/test/prod) and if so, is prod isolated from the others in the diagram?
- Single points of failure or single-component trust (e.g., one service that, if compromised, has a path to everything else) — worth flagging as an architectural concentration-of-risk issue even without a specific CVE.

**Supplier/third-party relationships (Annex A — supplier management)**
- Any external SaaS/API dependency — flag it as a boundary needing its own risk assessment/contractual controls, same as the PCI third-party note.

**Business continuity / resilience (Annex A — availability-related controls)**
- Redundancy shown for critical components (load balancers, multi-AZ, replicas)? A single instance of a critical component is a resilience finding, distinct from a confidentiality/integrity one — call it out separately.

**Logging & monitoring (Annex A — monitoring, logging, incident management)**
- Same lens as PCI Req 10 — is there a visible log aggregation/monitoring path?

## Severity guidance specific to ISO 27001
- No segmentation between tiers at all → High
- Sensitive data flow with no encryption-in-transit shown → High
- No centralized identity/access component across multiple services → Medium
- Single point of failure on a critical path with no redundancy shown → Medium
- No visible logging/monitoring component → Medium
